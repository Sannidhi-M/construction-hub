# the monorepo root's node_modules (nothing else needs it). Next's own .d.ts
# files then resolve `react`/`@types/react` starting from their own location
# in the root node_modules, finding the backend's React 18 types instead of
# this workspace's own nested React 19 types — so two conflicting copies of
# the global React type identities (ReactNode, JSX.Element, etc.) end up in

# have been verified to work) — it is a type-checker artifact only.
#
# The real fix is npm's `install-strategy=nested`, which gives every
